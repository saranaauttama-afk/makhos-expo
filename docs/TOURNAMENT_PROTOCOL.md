# Phase 2A paired A/B tournament protocol

This harness is measurement infrastructure, not an engine-strength change.
`scripts/headToHeadTest.ts` is deliberately disabled because the historical
prototype fixed identities to board sides, did not swap colors, ignored its
book flag, started every game at the initial position, called 200 moves a draw,
and reported an Elo point estimate without uncertainty.

## Players and games

An `EngineConfig` has a stable identity, display name, search control and
supported `SearchFeatureFlags` overrides. Each game creates a separate TT for
each identity. Every start produces one pair: A as P1/B as P2, then B as P1/A
as P2. Results are attributed to identity. Errors and the `maxPlies` safety cap
are excluded from scores and Elo rather than converted to draws.

The harness checks no-legal-move loss before searching and uses the production
position transition, inactivity policy and board-hash threefold history. The
full hash history starts at the supplied start position and is passed into
every search.

## Start suite

`makhos-measurement-starts-v1` is generated by a frozen xorshift32 seed and
algorithm. At each ply it sorts all legal moves and chooses a seeded index.
It stores the complete legal move sequence and resulting state, and rejects
duplicate resulting states. This is intentionally called a deterministic
measurement start set, **not** an authoritative Thai opening book: it has no
game-record provenance. Changing its seed, selection algorithm or size requires
a new version. The generator and start records are machine-readable TypeScript
data so legality is re-evaluated against the canonical move generator.

## Controls and statistics

Fixed nodes is the canonical Phase 2A control because it assigns reproducible
work. Fixed depth and fixed wall time are supported; time-only results are
explicitly non-canonical. Search output records main nodes, qnodes, completed
depth, elapsed milliseconds and derived NPS for every move and totals them by
engine.

Candidate score is `(wins + draws / 2) / completed games`; Elo is
`400 log10(score / (1-score))`. Infinite boundary estimates are serialized as
`null`, not capped to an arbitrary value. The 95% interval is a deterministic
20,000-sample **pair-level bootstrap**: whole two-game start pairs are sampled
with replacement, retaining the color correlation. A pair containing an error
or unresolved game is excluded from both estimate and interval. Small samples
normally give wide or boundary intervals and must not be called significant.
The pair/game records allow a future pentanomial or SPRT implementation without
changing raw artifacts.

`result.json` contains metadata, configs, starts, summaries and every move/search
record. `games.csv` and `pairs.csv` are tabular summaries. Raw runs live below `.tmp/`
and are not committed.

## Validation

`npm run test:tournament` regenerates the start suite twice, checks
deduplication, paired assignment, identical-engine move equality, identity
symmetry and repeat-run equality. `npm run tournament:smoke` runs both an
identical-default check and a one-variable plumbing check (`nullMove=false` on
the candidate only). The latter is not a strength experiment.

Limitations: Phase 2A is single-process and sequential because current search
internals contain module-level working state; wall-clock/NPS remain machine
observations; the generated suite is deliberately small and not a strategic
real-game corpus; no SPRT, distributed runner, adjudication, or authoritative
opening provenance is provided yet.
